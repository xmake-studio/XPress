# XPress

Android-приложение, которое сжимает видео ровно под заданный размер файла. По умолчанию это
10 МБ для Discord, и из этого лимита выжимается максимум.

## Возможности

- **Приём видео отовсюду**: «Поделиться» в галерее, «Открыть с помощью», системный выбор медиа
  или любой файл через «Открыть файл».
- **Любые современные форматы на входе**: H.264, HEVC/H.265 (включая 10-bit), AV1, VP9 и прочее,
  что умеет FFmpeg 8.1. HDR-ролики Xiaomi/Samsung (HLG, HDR10, Dolby Vision 8.4) переводятся
  в SDR тонмаппингом, чтобы цвета в Discord не были блёклыми. Поворот из метаданных учитывается.
- **Обрезка**: лента кадров с ручками, превью при перетаскивании, кнопки «Начало здесь» /
  «Конец здесь» и проигрывание только выбранного фрагмента.
- **Режимы**: целевой размер (пресеты 10/25/50/100 МБ или любое число), битрейт или постоянное
  качество (CRF). Кодек, разрешение, частота кадров, битрейт звука и скорость настраиваются вручную.
- **Удаление звука** одной кнопкой с любым пресетом. Освободившийся объём уходит в картинку.
- Готовый файл **сразу сохраняется в галерею** (`Movies/XPress`), а в приложении есть кнопка
  «Поделиться».
- Сжатие идёт в фоне через foreground-сервис с прогрессом в уведомлении. У приложения **нет
  доступа в интернет**. Метаданные (GPS, модель телефона) из результата вырезаются.

## Как выжимается максимум из 10 МБ

1. **Бюджет**. Из лимита вычитаются звук (AAC, авто: 128 → 96 → 64 кбит/с по мере сокращения
   бюджета) и оценка служебных данных MP4. Остаток целиком отдаётся видео.
2. **Разрешение и FPS по плотности бит**. Выбирается наибольшее разрешение (до 1080p), при котором
   на пиксель кадра приходится достаточно бит. При нехватке 60 к/с понижаются до 30. Чёткие 540p
   выглядят лучше, чем 1080p в квадратах.
3. **Двухпроходный x264** (`preset slow`, `aq-mode=3`). Первый проход анализирует сцену, второй
   распределяет биты туда, где они заметны.
4. **Подгонка**. После кодирования проверяется фактический размер. Если файл не влез или занял
   меньше ~95,5% лимита, второй проход повторяется со скорректированным битрейтом, а статистика
   первого прохода переиспользуется. В итоге файл занимает 96–99% лимита и никогда его не превышает.

`10 МБ` означает 10 000 000 байт: при любой трактовке лимита Discord это проходит.

### Почему H.264 по умолчанию

H.265 и AV1 при том же размере дают картинку лучше, но Discord показывает встроенный плеер не
везде: HEVC часто не играет в десктоп-клиенте и браузере, AV1 не играет на iPhone старше 15 Pro.
H.264 открывается у всех получателей. Остальные кодеки доступны в «Дополнительно».

## Сборка

Нужны JDK 17 и Android SDK 36.

```bash
./gradlew assembleRelease
```

APK лежат в `app/build/outputs/apk/release/`: `app-arm64-v8a-release.apk` для телефонов,
`app-x86_64-release.apk` для эмулятора. Release подписывается debug-ключом, чтобы ставиться
без настройки. Перед публикацией подпишите своим ключом.

Тесты:

```bash
./gradlew testDebugUnitTest
```

```bash
./gradlew connectedDebugAndroidTest
```

Инструментальные тесты генерируют на устройстве синтетические HDR/HEVC/повёрнутые исходники
и прогоняют настоящий FFmpeg.

## Стек

Kotlin, Jetpack Compose + Material 3 (динамические цвета), Media3 ExoPlayer,
[FFmpegKit (поддерживаемый форк)](https://github.com/ffmpegkit-maintained/ffmpeg) на FFmpeg 8.1
с libx264, libx265, libaom, dav1d и zimg. minSdk 29 (Android 10).
